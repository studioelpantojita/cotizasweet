# Cuentas, administración y despliegue de la revisión 2.3.0

La instalación local permite cotizar y enviar sin registro; User y Password propios de E&A Cotiza protegen las cuentas y la administración. La promoción y el recorrido de invitado se detallan en [NAVIDAD-INVITADOS-2026-11-23.md](NAVIDAD-INVITADOS-2026-11-23.md). Consulta `.local/ACCESOS-REVISION.html`; el registro público sólo crea clientes. `/admin` recibe solicitudes y permite crear clientes. `/cuenta` cambia la contraseña e invalida las sesiones anteriores. Las claves de revisión son exclusivamente locales y no se transportan en el ZIP de fuentes.

`setup-local.ps1` prepara dependencias y las cuentas. La herramienta local también puede repetirse desde la raíz: `node web/scripts/run-ts.cjs web/scripts/provision-accounts.ts`. No reemplaza una cuenta existente ni eleva automáticamente su rol. Al reiniciar el lanzador puede ser necesario volver a entrar; los documentos y las cuentas permanecen guardados.

## Configuración del alojamiento: aceptación pendiente

1. Define un origen HTTPS real y persistente en `APP_ORIGIN`. Establece `ACCOUNT_AUTH_ENABLED=true`, `ACCOUNT_ISSUER=<APP_ORIGIN>/accounts` y un `ACCOUNT_JWT_SECRET` aleatorio de 32 bytes en hexadecimal. El secreto de cuentas se comparte sólo entre web y API de cotizaciones; no se entrega al servicio RUC ni al navegador. Usa un `SESSION_SECRET` diferente y estable.
2. Conserva la configuración OIDC del despliegue documentada en `GOOGLE.md`, incluso cuando `OIDC_EXTERNAL_LOGIN_ENABLED=false`: la compatibilidad de los backends con OIDC sigue inicializándose. En particular, el backend alternativo Python de cotizaciones consulta sus metadatos al arrancar. El servicio Python RUC usado junto a .NET no requiere ese proveedor. El acceso externo no aparece en el formulario hasta habilitarlo y comprobar su configuración. Los perfiles sintéticos de las pruebas no son un proveedor para producción.
3. Configura las variables privadas en el alojamiento, nunca en el repositorio. Compose y la definición Railway incluyen las variables de cuentas en web y .NET. `scripts/preflight.py` comprueba la coherencia estática y no confirma que un proveedor real responda ni que sus credenciales funcionen.
4. Crea el primer administrador mediante una operación privada del propietario sobre la **base web persistente**. En una copia completa de fuentes con Node 24 y las dependencias web instaladas, configura `DATABASE_PATH` absoluto a esa base, las variables de cuenta anteriores, `ADMIN_USER`, `ADMIN_DISPLAY_NAME` y `ADMIN_PASSWORD_FILE` absoluto a un archivo privado con la contraseña. Desde `web` ejecuta `node scripts/run-ts.cjs scripts/create-administrator.ts`. No pases la contraseña como argumento ni publiques su archivo. La herramienta no modifica cuentas que ya existan y no imprime contraseñas. Esta operación requiere acceso al volumen correcto; no es un endpoint público ni un comando incluido automáticamente en la imagen standalone.
5. Respalda la base web (cuentas, documentos y solicitudes), la base de la API y la configuración privada necesaria para reconstruir la instalación. Para una copia coordinada, detén los escritores, usa `scripts/backup_sqlite.py backup` para cada base, verifica las copias y restaura primero en destinos nuevos. La prueba local de restauración no acredita recuperación en otro servidor. Conserva copias cifradas fuera del volumen y prueba la restauración en el alojamiento antes de la aceptación pública.
6. Confirma las tarifas referenciales del archivo común y la identidad comercial. Reconstruye los tres servicios juntos. El PDF señala los datos de muestra y los precios para pruebas. Configura y verifica aparte el correo comercial antes de anunciar entrega por correo.

Publicar las fuentes en GitHub es una operación distinta de desplegar los servicios en un alojamiento. La entrega GitHub está descrita en [ENTREGA-GITHUB-2.3.0.md](ENTREGA-GITHUB-2.3.0.md). El aprovisionamiento sobre un volumen remoto y la aceptación de producción deben verificarse en el alojamiento correspondiente; los perfiles sintéticos del CI sólo comprueban las fuentes y las imágenes. No uses las cuentas locales como credenciales de producción.
